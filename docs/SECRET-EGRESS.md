# Selected credential gates

New real provider calls run the pinned native Redact 1.1.0 verifier locally before provider transport or SDK credential loading. The factory validates Redact's complete pinned source inventory and the installed bundled Kujo runtime bytes. `KUJO_BIN` cannot replace this scanner. The scanner uses a private temporary document, sanitized environment, bounded output and a 30-second deadline. Temporary content and native audit records are removed on normal completion and handled failures. Abrupt process/host failure can leave private temporary files; this is not secure erasure.

The blocking native category is `remaining_api_key_patterns`. Redact's other high-risk categories include ordinary URLs and dates; those do not become credential blockers. Supplemental deterministic patterns cover selected PEM private-key headers, GitHub, AWS access-key IDs, Google API, Slack, Stripe, bearer tokens, and credential assignments. The exact policy is `config/secret-egress-policy.json`. Counts and SHA-256 identities are retained, never matched values. This is not comprehensive secret discovery, privacy filtering, obfuscation detection, or a substitute for credential revocation.

All real Codex, Ollama, OpenAI, Anthropic and Gemini proposal paths are guarded, including direct native SDK invocation. Explicit offline provider conformance fixtures remain labeled fixtures. A scanner error or matching selected pattern blocks the provider request; an unavailable scanner never silently permits transport. Both prompt and output schema are checked. Provider environment credentials are not scanned into documents or receipts.

New application, CLI, SQLite migration and Node dependency-upgrade missions set `secretScanRequired: true`. Before final promotion, the controller scans exact candidate source bytes and retains `artifacts/secret-source-scan.json`. Application/CLI/SQLite gates cover their application source tree. The bounded semver dependency pipeline covers its generated candidate source file; this does not claim to scan all third-party package contents. Source scanning is limited to 1,000 files/16 MiB, with bounded traversal, no symlinks/hardlinks/special files, stable file reads and repeated inventory checks. Binary assets are projected byte-for-byte into Latin-1 so selected ASCII patterns remain detectable; chunks overlap by 4,096 characters. Counts can overlap.

The source gate binds the existing candidate hash, a hashed-path file inventory, native selected-category reports and the policy/source/runtime identities. Promotion requires a fresh successful scan matching the retained immutable inventory. Blocked scan receipts remain preserved. Required-marker removal is rejected when retained source-gate or guarded provider footprints exist. Historical evidence without this policy is not retroactively labeled scanned. The recovery configuration identity includes the marker.

Hashes establish integrity within an evidence bundle, not authenticated scanner execution. Offline verification checks retained consistency and source identities; it cannot prove a historical process ran. Human approval and deployment authorization are never granted by these checks.

Validation: `node --test tests/secret-egress.test.mjs tests/provider-secret-egress.test.mjs tests/secret-artifact-gate.test.mjs tests/providers.test.mjs tests/provider-sdk.test.mjs` exercises actual pinned native scanner positive/negative paths and selected supplemental fake-credential fixtures. Provider blocking tests intentionally do not make external calls.
