# Known limitations

This integration increment is **not the requested feature-complete release**. The acceptance manifest records open requirements rather than equating files, availability or mocked outputs with completion.

- All 85 roles, including the 28 Chain of Command roles, and 136 complete skill packages are installed and integrity checked. Canonical schemas and restricted proposal intersections are enforced. Selected team consultations now run through native Dispatch with skills/provenance receipts. Every role's real semantic execution, escalation, performance and diverse provider combinations remain unqualified. Canonical Chain schemas themselves remain permissive; host restrictions are still required.
- The 45 workflow kits retain upstream maturity labels. Advisory routing covers 20 software mission types; that is not 20 qualified executable lifecycle implementations. Idea-to-reviewed-specification and standard Node existing-repository preparation add concrete paths but do not fill the entire matrix. Uniform upstream skill dependency metadata and complete compatibility/performance accounting remain unavailable or incomplete.
- Spec validates frozen pack contracts before construction. The specification pipeline obtains separate model review and retains draft identities. Five live attempts were rejected and preserved. A sixth precise static-greeting specification passed independent live review and native accounting at source `2cfc128`; this does not establish general specification quality. Model review does not prove test quality or execution. It creates no human seal. Full semantic contradiction detection, requirement change-impact analysis and broad test-quality evaluation remain incomplete.
- Native RunLedger, CaseFile, Eval, selected ShipCheck and Lens integrate with independent release gates. Lens evidence includes screenshots and automated accessibility at the declared threshold; visual baseline comparison and comprehensive accessibility compliance are not established. Security/dependency release checks remain narrower than the full requested policy.
- Scout/Scent/Redact and native change-tool adapters have narrow real-tool fixture qualification. Original context snapshots and intermediate reports remain sensitive; redaction is not exhaustive and generated context does not grant authority. Concord remains experimental. Fence checks imports, not host effects. Kennel integration validates manifest structure/source references only; it does not resolve, install, verify signatures, scan vulnerabilities or prove supply-chain safety. Ability/Relay/Tribunal, durable RAG/knowledge, PackWrite/Muzzle and other audited capabilities still require qualified integration.
- Codex and local Ollama pass bounded live schema checks. Codex has complete mission/retry evidence and a selected-team v3 run; the latter used changing source and is not a final-source qualification. A local Ollama revalidation completed through independent review, Workcell, Lens and accounted release; its prior larger-model timeout remains failed. This qualifies the recorded revalidation path, not general software construction with that model. Provider comparisons, enforceable usage/cost reservations and broader role-specific model qualification remain open. Anthropic/Gemini are not supported execution paths merely because audited SDK adapters exist.
- Node HTTP/static/SQLite remains the application construction path. Python/Kujo and TypeScript qualification is limited to the exact rootless CLI fixtures/images recorded in [CLI-RUNTIME-QUALIFICATION.json](CLI-RUNTIME-QUALIFICATION.json). Native Go/Rust qualification exposed a writable shared-mount boundary despite restrictive mode bits. Unsafe v1 remains disabled. The replacement v2 two-lease/read-only-mount profile is qualified for installed Go/Rust CLI fixtures only: five cases per language, seven shared security checks and installed CLI positives, using pinned Workcell `144ab49da88a17fd0d786d01d98030d7ec7798cb`. This does not qualify full model-backed language missions, services or frameworks. Package-managed frameworks, dependency lifecycle scripts, PostgreSQL and general service profiles remain unsupported.
- Evidence integrity, source binding and optional trusted-key signatures work offline. They do not prove actual execution, human identity or deployment authority. New v3 approvals require Lens and native accounting/policy/Eval evidence. Historical runs remain explicit about missing provenance. Imports and recovery snapshots archive evidence; they cannot restore a mission's execution authority.
- Default MCP remains read-only. The separate local control transport requires explicit grants and records owned operations; fixture subprocess tests do not qualify all external hosts, multi-user service operation or live model submission combinations. Factory Floor remains read-only and displays recorded claims; synthetic fixture/browser qualification is not proof that its displayed missions actually ran.
- Git onboarding/worktree/commit/conflict and review-only PR preparation are available. GitHub check reading has a live public observation; transport fixtures cover issue ingestion, not private account/publishing qualification. Existing-repository repair is restricted to dependency-free standard Node implementation files. A real standard Node repair completed with v3 approval; recorded-approval patch replay separately checks preservation. Neither qualifies arbitrary repositories or final-source releases. No automatic push, PR publication, merge, deployment or public release is authorized.
- Existing watchdog cleanup and native process-kill tests pass. Retained native inspection/plans, archival snapshots, terminal backups and retention dry-runs are implemented. Production resume remains disabled because fixed worker artifact names and uncertain effects require reconciliation/new attempts. Automatic recovery, restoration, global quotas, cost ceilings, rotation and notifications remain incomplete.
- Current-machine and same-host clean-checkout results do not qualify fresh Linux/macOS machines, WSL2, fully offline installation, upgrade or rollback. Final-source aggregate/runtime checks must be repeated after concurrent integration settles. Do not transfer old receipts across changed source, pins or images.
- The upstream VideoOps Kujo validator fails with VM Stack underflow on Kujo 1.9.0; independent schema checks do not resolve it. Agent manifest correction is pinned from a review branch, not represented as a merged release.

Foreman is excluded. Remote/cloud/private/commercial capabilities are optional or unavailable. No capability may silently fall back to candidate execution on the host.

- Watchdog integration is local terminal/on-demand snapshots using native validation and SQLite, not continuous model/tool instrumentation, cross-run aggregation or a proxy/exporter. Repeated observations must not be summed as new model calls. Content-free hashes still permit correlation. Observations grant no approval and are not actual execution proof; missing usage/cost remains unknown.
