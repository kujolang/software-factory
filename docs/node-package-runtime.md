# Bounded Node dependency upgrades

This profile admits one Node `app.mjs` CLI and exactly one pinned `semver` dependency (qualified versions 7.7.2 and 7.7.3). It does not support arbitrary npm graphs, React, services, native addons, package scripts or dependency lifecycle hooks. Its runtime image and trusted build runner are controller-owned. Four actual Workcell fixtures passed at the pinned image: positive execution, wrong-answer rejection, timeout rejection, and protected-lock write denial, with successful cleanup. Evidence: `.runtime/node-package-qualification/execution-5kUdsO/qualification.json`. The subsequent actual Codex/native Dispatch mission `package-cFPUOi` passed independent contract/source/release reviews, a semver 7.7.2 baseline, semver 7.7.3 acceptance and fresh revalidation, followed by RunLedger terminal accounting. Its four provider calls recorded 44,307 input tokens, 13,056 cached input tokens and 2,113 output tokens; cost was unreported. Evidence: `.runtime/node-package-qualification/live-qualification.json`. The first failed attempt `package-MaZzDN` remains retained: a no-blocker review returned `proposed`, which the strict gate rejected; the fresh attempt used an explicit pass/fail review prompt. The successful controller source was HEAD201ee9e with concurrent dirty files separately recorded by controller provenance, not a clean-checkout claim.

The operator supplies a reviewed contract with exact package and lockfile data, finite CLI cases, old version and mission. Its seal binds identity and is not proof of human review. The current source and old lock are independently frozen. The candidate can propose only `app.mjs`; it cannot alter locks, caches, tests or review instructions.

Explicit prefetch reads exact official registry metadata and a bounded tarball, verifies SHA512, and runs the qualified bundled npm 11.20.0 advisory command in a clean temporary HOME with separate empty npm config files. It neither extracts packages nor executes candidate or lifecycle code on the host. The report records npm version/CLI digest, lock and tarball identities, advisory response and observation time. Missing, failed, nonzero-vulnerability or older-than-seven-day audit observations fail admission. These are time-specific registry observations, not authenticated execution or guaranteed vulnerability absence. No external source/credentials are sent; only the reviewed package graph is audited. This is not a general ecosystem security scanner.

Inside a rootless, network-none Workcell lease, a fixed trusted runner writes the reviewed package/lock and SRI cache to a new private tmp directory. It executes only `npm ci --offline --ignore-scripts --no-audit --no-fund --no-bin-links`. The installed source and dependencies become root-owned read-only files. Separate Docker exec requests run only `node app.mjs` as UID/GID65534, with finite args and strict timeout/output bounds. The host compares observed exit status/stdout against the independent contract and retains raw argv/results. The harmless trusted health wrapper is lease bootstrap and does not claim candidate HTTP service compatibility. Cleanup and independent watchdog remain mandatory.

Native Dispatch sequences Spec validation, independent contract review, real old-version baseline, scoped implementation, separate source review, new-version execution, release review and a second fresh verification. RunLedger terminal accounting precedes a reviewable local candidate. CaseFile retains failures. Release reviewers receive exact source, contract/cache digests, raw install/test status, actual argv and local evidence references. No agent can grant deployment or human approval; a fixture-provider result cannot approve a software release. There is no retry-in-place or automatic breaking dependency adoption.

## Commands

`node scripts/node-package-install.mjs prefetch OPTIONS.json` accepts exactly `version` and a fresh `destination`; it performs explicitly requested registry network reads. Prefetch old and new versions separately.

`verify OPTIONS.json` accepts exactly `sourceFile`, `contractFile`, `cacheDirectory`, and a fresh `evidenceDir`; candidate code executes only inside Workcell. This is execution evidence, not a release approval.

`run OPTIONS.json` accepts exactly `inputFile`, `baselineCache`, and `targetCache`. The input uses `kujo.factory.node-package-mission-input/v1`, a sealed target `contract`, and `current` with `package`, `lock`, and existing `source`. This invokes the configured provider and requires authorized usage. No package credentials, source paths, arbitrary commands or output-directory overrides are accepted from a candidate.

Run deterministic checks with `node --test tests/node-package-contract.test.mjs`. `node scripts/node-package-qualify.mjs` requires explicitly prefetched task fixtures under `.runtime/node-package-qualification` and a qualified existing engine image. Engine/model qualification results are separate from these contract tests. Never infer broad npm support from the semver fixture.
