# Optional Lens visual baselines

The factory uses the pinned Lens `bridge/visual-diff.py` comparator rather than implementing a pixel engine. Lens commit `91049646d70c11bf0c6071f39cf7dfac6b1ba70b` (1.1.1) compares RGB channels, counts pixels whose largest channel difference exceeds 10, and reports a six-decimal ratio. Its pass decision uses the unrounded ratio. Pillow 12.3.0 and NumPy 2.2.6 are the upstream optional test dependencies. Dimension mismatch and missing dependencies cannot pass.

`factory/visual-baseline.mjs` provides preparation, inspection, explicit approval, and comparison APIs. Preparation verifies an existing native Lens binding and copies its two bounded PNGs into a new directory. It retains the complete native Lens artifacts and Workcell record closure under `origin/` and revalidates that closure on every inspection. Each PNG must match the original named viewport hash and dimensions; a new approval hash cannot bless swapped screenshots. It records the source hash, native binding hash, Lens commit/version, viewport definitions, and exact Workcell image. The image identity covers the packaged browser and fonts; pinned Lens code defines the browser defaults. Dynamic page content is not normalized. Different image identities require a separately reviewed baseline.

Preparation does not approve anything. An operator must inspect the screenshots and provide the exact baseline JSON SHA-256, their identity, and explicit confirmation to `approveVisualBaseline`. The resulting receipt is an unsigned local operator assertion, not authenticated identity, cryptographic attestation, or software release approval. There is no overwrite/update API. A changed baseline needs a new directory and another explicit review. Agents and mission execution must not call approval on their own output; callers must enforce their control-interface authorization. The optional comparison is not wired into release policy.

Comparison requires a verified Lens binding and its existing Workcell lease. It executes only the pinned native comparator on retained screenshot bytes as the protected browser UID, with fixed paths, bounded input/output and timeouts, within the rootless, network-disabled Workcell boundary. No candidate code or image decoder executes on the host. The factory checks PNG header dimensions before decoding, permits at most 16 million pixels and 2 MB per image, and records native output, exact command, stdin hash, both PNGs, baseline metadata and approval. It checks native pixel counts, dimensions and verdict consistency. This is consistency validation, not proof that an unsigned external record is authentic.

The standard browser image does not install Python/Pillow/NumPy. An explicitly qualified optional image is required; absence fails closed with no host fallback. Unit tests use inert synthetic metadata and PNG headers and do not qualify browser execution. Actual qualification passed in `.runtime/visual-baseline-qualification/execution-IhVFSF/qualification.json`: independently captured positive, changed-pixel negative, direct native dimensional mismatch, and rejection of unapproved/forged records. The optional image is `sha256:d2453fc8e7815e4acc2906105c3c1f92e1d455f74f5332e4ce3abeda073d8b8d`. Five deterministic baseline tests and eight existing Lens tests pass. Earlier qualification attempts remain historical and do not qualify the final origin-bound baseline contract.

All comparison results are advisory. A passing comparison neither approves its own baseline nor grants release, merge, deployment or publication authority. Screenshots can contain private rendered data and should be reviewed before export. Failure receipts remain in the supplied fresh output directory.

Build the optional image with `node scripts/prepare-visual-baseline-image.mjs`. The builder verifies the existing base image locally, downloads the two exact wheels from `files.pythonhosted.org`, checks their byte counts and SHA-256 values from `config/visual-runtime.lock.json`, and installs only those wheels with network disabled and pip `--no-index --only-binary=:all: --no-deps --require-hashes`. It leaves the default factory image unchanged. `FACTORY_WORKCELL_IMAGE=kujolang/factory-visual:local` explicitly selects the image for browser missions; new baselines must use the same image as their comparisons.

`node scripts/qualify-visual-baseline.mjs` exercises actual native Lens browser capture and native pixel comparison. Its operator identity is a synthetic test fixture. The dimension mismatch negative directly invokes the pinned comparator on actual mobile and desktop PNGs inside Workcell; it never passes through baseline approval and is not valid baseline provenance. It does not claim that fixed-viewport Lens captures change dimensions when page content grows. All failed qualification attempts remain under `.runtime/visual-baseline-qualification`.

Retain the baseline directory (including `origin/`) with comparison records when handing evidence to another operator. This optional API does not yet provide a standalone portable visual-verifier command or a binding release-policy gate.
