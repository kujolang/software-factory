# Disposable SQLite migration qualification

The SQLite subsystem accepts a bounded SQL migration and an independently supplied sealed contract. The contract identifies source and target `user_version`, old schema/data seed statements, expected old rows, expected post-migration SELECT rows, and exact before/after column declarations (name, type, nullability, default and primary-key position). The seal establishes byte identity, not correctness or human approval. Contract review occurs before generation; source/security review and release review use different canonical roles from the backend implementation role.

The controller runs a fixed trusted Node `node:sqlite` harness as UID/GID 65534 in the existing rootless Workcell. It never executes candidate SQL or JavaScript on the host. The normal no-network, read-only root filesystem, private source mount, seccomp, no-new-privileges, resource controls, independent watchdog and cleanup verification remain unchanged. No image rebuild is needed. Exact Node and image identities are declared in `config/sqlite-migration-profile.json`; the narrow SQL profile passed nine actual representative and hostile Workcell cases; see [qualification record](SQLITE-MIGRATION-QUALIFICATION.json).

A separate fixed disposable rollback database first executes the candidate SQL and then a controller-forced exception before COMMIT; the runner must prove that exact old version, column declarations and reviewed rows survived. Every successful mission includes this candidate-specific rollback evidence. Each forward database is seeded with reviewed old data, checked independently, migrated inside a controller-owned transaction, checked for integrity and expected results, closed/reopened, then inspected after a Workcell application restart. A fresh full migration repeats after independent release review. The SQL authorizer rejects attached databases, paths through ATTACH/VACUUM, PRAGMA, explicit transaction/savepoint control, extensions, virtual tables and triggers. Only a bounded allowlist of SQLite scalar/aggregate functions is available. SQL, contract, query rows, output, database pages and execution time are capped. Source/contract files reject links, special files, oversized inputs and unstable reads.

A SQL execution failure rolls back the controller transaction; the evaluator independently verifies the original version, schema and reviewed old rows. A killed process, timeout, failed post-commit assertion or cleanup error is a failed evaluation and does not claim a verified rollback. This does not implement reverse migrations, compatibility with arbitrary production data, online migration, PostgreSQL, framework migrations, automatic deployment or production database access. The finite reviewed fixture is an example of behavior, not exhaustive proof.

`evaluateSQLiteMigration({sqlFile, contractFile, evidenceDir})` is a trusted controller API. `runSQLiteMission({input})` uses native Dispatch and canonical roles, native Spec validation, actual Workcell evaluations, RunLedger terminal accounting and CaseFile failures. Input shape is `kujo.factory.sqlite-mission/v1` with `mission` and `contract`. No model selects the runner, filesystem paths, authorization policy or commands. `verifySQLiteMission` verifies the recorded source/contract/role and Workcell identities before issuing a local reviewed artifact. The typed `database-migration` route delegates only to the fixed public SQLite mission controller after its real execution path and standalone offline evidence verification passed.

`node --test tests/sqlite-migration.test.mjs` validates the sealed input and filesystem boundary without an engine or candidate execution. `node scripts/qualify-sqlite-migration.mjs --workcell` performs actual positive migration/restart plus hostile ATTACH, PRAGMA, transaction escape, partial mutation rollback, incorrect data, extension loading output-row overflow and timeout cases. It preserves every failure and records actual source/Workcell receipts. No mocked success qualifies the profile.

The controller-only `fixtureOutputs` API seam supports deterministic rejection tests, is absent from mission input and CLI permissions, records `fixture:true`, and cannot promote a software artifact. Native tests prove canonical implementation verdict `proposed` is admitted while independent reviewer `proposed` is rejected, failure CaseFile/RunLedger evidence survives, and candidate path changes cannot mutate the reviewed input. Release reviewers receive exact executed argv, exit/status/deadline receipts and actual seed/rollback/forward/restart observations, not inaccessible artifact references alone.

Run the reviewed finite example with `npm run factory -- sqlite-mission examples/sqlite-migration.json`. It performs real provider calls and Workcell execution; no production database is accessed. The general typed mission interface accepts `{schema:"kujo.factory.mission-input/v1", type:"database-migration", mission:"...", contract:{...}}`. Its closed contract rejects SQL command/executable paths, fixture outputs, provider overrides and unrecognized effects. `mission validate` grants no execution authority; `mission execute` delegates the admitted contract to `sqlite-mission`.

Real Codex mission `sqlite-8fUBdG` completed on 2026-11-13 with native Spec, independent contract/security/release review, candidate-specific forced rollback, forward migration/reopen/restart and fresh repeated acceptance. Native RunLedger passed with 45,894 input and 1,981 output tokens; cost was unavailable. Portable export and a copied standalone verifier passed strict five-command/old-data/schema/rollback/source/accounting consistency checks. The separate qualification summary records exact hashes and retained failed attempts, including legitimate independent reviewer rejections that led to stronger acceptance and review evidence. `node --test tests/sqlite-migration.test.mjs tests/sqlite-mission.test.mjs tests/mission-workflows.test.mjs` covers closed admission, link bounds, canonical proposed verdict semantics, failed native accounting/CaseFile preservation, prohibited file effects and fixed route delegation.
