# Local Watchdog observations

`factory/telemetry.mjs` exposes `collectMissionTelemetry(runDirectory, {parent})` and an observational controller hook `observeMissionTelemetry`. The hook returns an unavailable result if collection fails; it does not change mission status, retry work, issue approval, or weaken a gate. `telemetryCommand` supports `verify` and `collect`. The normal installer integration can call `setupTelemetry`; the standalone command is `node scripts/setup-telemetry.mjs`.

The adapter uses Watchdog 1.2.2 at `7a0bd9a63d68421831ed66d6eed29805c48e1b24`: `watchdog_native_batch_normalize`, `watchdog_telemetry_repository_validate`, `watchdog_telemetry_repository_insert`, and `watchdog_ensure_schema`. The pinned six-file closure contains library code, version and license; no upstream server, proxy, exporters or installer is started. No candidate program runs on the host. Watchdog owns canonical records, semantic validation, SQLite schema and insertion. Its shared module attempts only its two fixed pricing-catalog paths in the fresh private directory; neither catalog nor pricing estimation is enabled.

Read inputs are `run.json`, `events.jsonl` and bounded `artifacts/*-receipt.json` provider records. Limits are 1 MB per JSON record, 4 MB per journal, 1,000 journal events, 1,000 directory entries, 100 receipts, and 1,000 usage entries per receipt. Native batches contain at most 100 observations. Source ancestors and selected files must be ordinary non-symlink paths. Native execution has a minimal credential-free environment, a 30-second timeout and a 16 MB output ceiling. Source files are never copied into the observation workspace.

Content is off. The controller admits only fixed event names, sequence/timestamp numbers, provider enums, hashed identities, observed duration where present, and nonnegative observed token counts. Mission text, arbitrary event names, model/role strings, summaries, prompts, responses, tool arguments/results, source, provider errors and credentials are omitted. Unknown input/output token values remain JSON null in native canonical storage; there is no invented total. Costs remain null in the factory binding and absent from native cost entries. Provider receipts without observed timing remain instantaneous observations with timing explicitly unknown. Event timestamps are retained as metadata; these events are observations, not reconstructed spans or proof of execution.

Each collection creates a separate private local SQLite database and canonical JSON export, plus source SHA-256 identities, a sanitized native input, an execution receipt and a binding. Native failure output is hashed rather than copied, and a generic failure record is preserved. This is an on-demand or terminal snapshot, not continuous telemetry, cross-run aggregation, a live proxy, or a remote exporter. Repeated snapshots are independent observations and must not be summed as separate model calls. Raw artifact paths are not included in source records; receipt filenames are hashed. Database, source hashes and hashed identifiers can still be sensitive correlation metadata.

Qualification uses real pinned native libraries with synthetic fixtures: SQLite canonical insertion, retained null usage and no costs, source/secret omission, malformed input, path/symlink/size rejection, and failure remaining observational. It does not establish network/exporter qualification or authenticity of the original controller claims. Telemetry carries no approval, deployment authority or actual execution proof; the original independent evidence remains authoritative.
