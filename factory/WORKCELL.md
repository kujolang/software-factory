# Workcell execution boundary

Every factory candidate API server, syntax build, browser check, and product demo runs inside a rootless Docker Workcell. Missing engines, images, security controls, receipts, or cleanup evidence block the run. There is no host execution fallback.

Build the trusted image with `node factory/build-workcell-image.mjs`. Use a reviewed local Docker endpoint, then run `node factory/workcell-tests.mjs`. The normal factory uses the same lease implementation. `FACTORY_WORKCELL_IMAGE` selects an installed image; the lease resolves and pins its image ID. `FACTORY_WORKCELL_BIN` and `FACTORY_WORKCELL_KUJO` select trusted local executables.

The definition requires native-guarded rootless Docker, default seccomp, no network, no capabilities, no new privileges, a read-only root filesystem, bounded memory/CPU/processes/output/time, and a disposable workspace. Only that workspace is mounted beneath the image-owned UID0 mode0700 directory `/workspace/private`, whose parent permissions are checked at runtime; no host home, credentials, Docker socket, or factory evidence directory is available inside. The actual Docker configuration and effective cgroup/process controls are recorded and checked.

The trusted keepalive copies the candidate into a root-owned read-only snapshot before any candidate process starts. The application runs as UID65534. Protected control files belong to UID0; browser files belong to UID1000 in a mode0700 directory created before candidate launch. The disposable Workcell mount remains writable for the trusted initializer under the runtime contract, but UID65534 and UID1000 cannot traverse its private read-only-image parent. Every non-root exec starts in `/tmp`, never inside the mount. The initializer moves its working directory to `/opt/factory` after copying. The application can write only to container tmpfs, charged to the 1 GiB memory limit; it cannot fill the host workspace volume. Direct bind access and `/proc/1/root`, `/proc/1/cwd`, and `/proc/1/fd` access are covered by live probes. The application cannot replace image-owned check code or write host receipts.

The API oracle stays on the host and talks to one fixed loopback endpoint through an image-owned bounded HTTP bridge. Candidate stdout is diagnostic data, never an acceptance result. Browser checks and demo rendering execute inside the same container as UID1000 with a pipe transport. Chromium's nested sandbox setting is recorded separately from the outer Workcell boundary; this does not claim protection against browser or kernel exploits. The host sees copied, size-bounded reports and media from protected paths, not candidate JavaScript.

Each lease retains the definition, input counts, engine doctor result, observed container settings, effective controls, Workcell receipt/manifest/logs, native integrity verification, and confirmation that its owned container was removed. Unexpected Workcell termination fails the gate. Failed leases still attempt cleanup. An independent image-owned PID 1 watchdog enforces the validated 1–300 second lifetime even if the entire host controller process tree is killed. Its exit stops every container process. Abrupt SIGKILL can prevent host-side receipt finalization and leave stopped container metadata and disposable workspaces; operator recovery must remove those owned leftovers. The controller-death regression kills the host process tree, observes autonomous exit 124, then verifies explicit recovery removed the owned container and workspaces.

`node factory/workcell-controller-death-test.mjs` verifies the independent watchdog and explicit recovery. Live hostile probes cover host canaries, inherited environment, protected control/browser/image/source writes, signaling UID0, Docker socket access, external network access, source link admission, and unavailable-engine rejection. These are concrete regression probes under the observed local engine. They are not a universal sandbox-escape proof, public hosting qualification, or production deployment approval. The engine VM, host kernel, trusted image, Workcell executable, and controller remain trusted infrastructure.
